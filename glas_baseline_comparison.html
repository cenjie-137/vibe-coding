① 关于 "U-Net 基线 0.768"：这是一个口径错配的伪基线

在公开文献里，"0.768" 对应的是 U-Net 在 GLaS 上的两个值，都不是 testB 对象级 Dice：

  • U-Net 像素级 IoU = 76.81%（HEA-Net 综述表）/ 76.84%（TAC-UNet）—— 这是像素级语义分割的 IoU，不是对象级 Dice，也不是 testB。对应像素 Dice ≈ 86.3%。
  • U-Net 对象级 F1（testA）= 0.766（J Integr Bioinform 2025，作者自行训练 U-Net）—— 是 F1 不是 Dice，且是 testA 不是 testB。

→ 之前 LLM 轨道把其中一个值写成 "U-Net 基线 0.768" 画在 testB 对象级 Dice 图上，属于指标类型 + 子集双重错配。用它判断"是否超过基线"不成立。这正是本研究要暴露的 vibe coding 痛点之一：LLM 会把不同口径的数字当成可比基线。

② 公平比较下的真实位置（官方对象级口径）

把口径统一到 GLaS 官方协议后，nnU-Net 基线 agent 的结果是：testA ObjDice 0.872 / F1 0.774，testB ObjDice 0.818 / F1 0.611。落在已发表方法的正常区间内，testB ObjDice 甚至高于挑战赛冠军 DCAN(0.781)；但 testB ObjF1 明显偏低，原因是 nnU-Net 默认不做实例分离，粘连腺体被并成单个连通域（→ 后处理可白涨 +0.12，见第 4 节）。

  1. "0.768" 不可信：它是 U-Net 的像素级 IoU(76.81%) 或 testA 对象级 F1(0.766)，被 LLM 当成 testB 对象级 Dice 基线使用 —— 这是本研究记录到的 vibe coding 痛点实例（口径混淆 → 错误基线 → 错误结论）。
  2. 没有公开的 nnU-Net GLaS 基线：nnU-Net 原论文未收录 GLaS，文献中也未见常用的 nnU-Net-GLaS 对象级数字。因此我们这次跑的 nnU-Net v2 基线本身就是该任务的 nnU-Net 参照，是一个可写进论文的补充贡献。
  3. 我们的真实水平：testA ObjDice 0.872 / F1 0.774，testB ObjDice 0.818 / F1 0.611 —— 分割质量（Dice）已进入第一梯队，唯一短板是 testB 的实例分离（F1）。
  4. 最高性价比的下一步：给 nnU-Net 推理加"剔除小目标(≥30px) + 2~3 次 3×3 开运算"，ObjF1 可白涨 testA +0.08 / testB +0.12，无需重训。
  5. 口径统一是当务之急：重跑 LLM 轨道推理 → 官方口径重评 → 才能给出"LLM vs nnU-Net vs 已发表方法"的可信三方对比表。

6 · 组会讲稿要点（3 分钟版）

  1. 先破题：之前图上标的 "U-Net 基线 0.768" 经查证是口径错配——公开文献里那个 0.768 是 U-Net 的像素级 IoU（或 testA 的 F1），不是 testB 的对象级 Dice。所以"有没有超过基线"这个结论不成立。（这本身就是一个很好的 vibe coding 案例：LLM 把不同口径的数字当成了可比基线。）
  2. 再给公平对照：统一到 GLaS 官方对象级口径后，把已发表的 U-Net / CUMedVision1 / DCAN / MILD-Net 和我们今天跑的 nnU-Net v2 基线 agent 放在一起——我们的 testA ObjDice 0.872、testB ObjDice 0.818，testB 的 Dice 已经超过挑战赛冠军 DCAN。
  3. 亮短板：但 testB 的 F1 只有 0.611，全表最低——原因是 nnU-Net 默认不做实例分离，粘连腺体被并成一个连通域。这是"分割质量好、检测差"的典型特征，也说明对象级评估的胜负手在实例分离。
  4. 给解法：加一个廉价后处理（剔小目标 + 开运算），F1 可白涨 +0.12，不用重训。这条已经做了消融，数据是现成的。
  5. 收尾：LLM 轨道的数字目前口径不一致，暂不能并入同一张表；下一步重跑 LLM 推理统一口径后，就能给出完整三方对比。
