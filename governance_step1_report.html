01我们在做什么

人只写一份规则文件，之后 Agent 自主完成「查文献 → 复现 → 改进 → 判断该不该换路子 → 换下一条」的完整循环， 中途不打断，直到达标或路线池耗尽。重点不是跑得久、跑得高，而是跑得可信、跑得省。

人做什么
只写 AUTONOMY_POLICY.md 一份规则（目标 / 阈值 / 红线 / 终止条件）。写完退出回路。
Agent 做什么
按规则自主跑完 8 步流水线，每一步都留痕；判定由代码给出，不由模型"感觉"。
凭什么信它
把当时的状态快照存下来，事后用同一个判定器再判一遍。判出一样 → 说明确实是规则在决定，不是临场发挥。

02与对标工作的不同点

对标工作（Camyla，中科大 / 上海 AI Lab，2026）的核心是规模：让 Agent 长时间跑、堆算力、冲指标。 我们回答另一个问题：它跑出来的结果，我凭什么信？　来源：本项目《前沿文献调研报告》。

维度Camyla（对标）我们
关注点跑得久、跑得高跑得可信、跑得省
判定方式结果导向，判定依赖模型判定逻辑写死在代码里，换会话换模型结果一致
数字可信报出来即可每个数字都要能追问"从哪来的"，无来源直接作废
算力定位规模导向消费级算力（32G 单卡）下的节俭自主
交付形态一套方法 / 结果治理协议 + 参考实现（别人可拿去复跑）

03三个创新点：把口号变成机制

"可信"最容易停留在口号。这三件事把它变成能跑、能复现、能被第三方验证的东西。

创新点 1

红线变成能跑的代码

把"不许改口径、不许编数字、不许自己改规则"这些原则，变成 9 个当场能审问 Agent 的函数。过不了就是违规，不靠自觉。
python redlines.py --selftest
23 条对抗用例（每条红线一个应通过、一个应拦下）
创新点 2

溯源账本

每个数字、每个动作都留痕，且只许追加、不许改写——已写下的痕迹无法被 Agent 事后"美化"。论文里"来源覆盖率"就是一硬指标。
python ledger.py --scorecard
当前来源覆盖率 87.5%（7/8 条数字带可核实来源）
创新点 3

可重放判定

给定同样的状态和规则，判定器必须复现出一模一样的决策序列。这是"可信"两个字的技术证据。
python replay.py --trace ...
硬比对 decision+reason；链哈希连文案改动都能检出

为什么这个哈希重要： 论文里报一个哈希，任何人拉下代码跑一遍，哈希对得上就说明整条决策链没被改过。 我们对"改过"的定义很严——硬比对 decision + reason 两层， 而链哈希连 detail 文案都算进去，连改文案都会被检出。 自检里专门放了一条"篡改留痕"用例，验证它一定会被发现。
一个刚被验证出来的好性质： 本次 policy 从 v1.2 升到 v1.3（新增 BEETLE、回填 PUMA 基线）， 但这条 GLaS 决策链的哈希没有变。原因是哈希算的是"决策序列"，不是配置文件版本—— 规则改了但只要不影响这个任务，判定就不该变。反过来，一旦规则改动真的影响了判定，哈希必然变。 这正是我们想要的语义。
